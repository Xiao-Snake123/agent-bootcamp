# Agent（智能体）系统学习教学大项目 · 规划书

> 一份面向"从概念到落地"的 Agent 教学项目整体规划。  
> 设计原则：**概念先行、动手印证、由点到面、最终贯通**。

---

## 一、项目概述与目标

### 1.1 我们要解决什么
学习 Agent（智能体）最大的痛点是"看得懂原理，写不出系统"——知识点零散（工具调用、记忆、规划、多智能体……），彼此割裂，学完不会整合。本项目用**双区结构**把"懂"和"会"绑在一起：每个理论点立刻配一个可运行的小项目；全部学完后，用一个综合大项目把所有模块串成一条能跑通的真实链路。

### 1.2 总目标
- 让学习者建立 **Agent 的统一心智模型**（感知—思考—行动—记忆—协作的闭环）。
- 掌握主流 Agent 能力的**原理 + 工程实现**，而非只会调 API。
- 能独立设计并实现一个**多模块协同的端到端 Agent 系统**（大项目）。

### 1.3 适用对象
- 有基础 Python 能力、了解 LLM 基本概念（会用聊天模型即可）的开发者/研究者。
- 无需提前掌握 Agent 框架，框架在项目中渐进引入。

## 二、整体架构设计

### 2.1 架构总览

```
┌──────────────────────────────────────────────────────────────────────┐
│                      中央学习主线（Learning Spine）                      │
│   一条贯穿始终的主线：以"一个最小可运行 Agent Loop"为种子，逐步长成系统    │
└───────────┬──────────────────────────────────────────────┬───────────┘
            │                                              │
   ┌────────▼─────────┐                         ┌──────────▼─────────┐
   │  文字性教学区       │    衔接层（Bridge）      │   项目教学区          │
   │  (Theory Zone)    │ ──── ①讲解后动手 ────▶   │   (Lab Zone)        │
   │                   │ ◀─── ②做完回扣理论 ────   │                     │
   │ · 概念            │                         │ · 每点一个 Mini 项目 │
   │ · 原理            │                         │ · 可运行 + 可验证    │
   │ · 范式/伪代码      │                         │ · 输出物=能力证据    │
   │ · 常见陷阱        │                         │                     │
   └────────┬─────────┘                         └──────────┬─────────┘
            │                                              │
            └──────────────┬───────────────────────────────┘
                           │
                  ┌────────▼─────────┐
                  │  综合大项目        │
                  │  (Capstone)       │
                  │  整合全部模块到    │
                  │  一个真实系统      │
                  └──────────────────┘
```

### 2.2 三大构成
1. **中央学习主线（Spine）**：不是独立内容，而是一条"贯穿线索"——以"先跑通一个最小 Agent Loop"为种子，每个新知识点都在它上面加一个模块，让学习者始终看到"全局在长大"。
2. **文字性教学区（Theory Zone）**：按学习路径拆解的概念章节，负责"为什么"和"是什么"。
3. **项目教学区（Lab Zone）**：与理论一一对应的动手项目，负责"怎么造"和"跑起来"。
4. **综合大项目（Capstone）**：收口，把全部模块组装成端到端系统。

## 三、两大区域的划分与衔接方式

### 3.1 文字性教学区（Theory Zone）
每章固定结构，保证"教学一致性"：

| 小节 | 作用 |
|------|------|
| 学习目标 | 学完你能做什么（可验证） |
| 核心概念 | 定义、边界、与其他概念的关系 |
| 工作原理 | 机制拆解 + 伪代码/流程图 |
| 主流方案 | 代表框架/论文/范式（如 ReAct、Plan-and-Execute） |
| 常见陷阱 | 新手最容易踩的坑 |
| 自检题 | 3–5 题检验理解 |
| 动手引子 | 指向下一个 Lab（衔接出口） |

### 3.2 项目教学区（Lab Zone）
每个项目固定结构，保证"产出可验证"：

| 小节 | 作用 |
|------|------|
| 项目主题 | 一句话说明要造什么 |
| 能力目标 | 对应哪个知识点、练出什么能力 |
| 任务拆解 | 步骤清单 |
| 验收标准 | 明确的"跑通"判定 |
| 参考实现要点 | 关键代码思路（不替学习者写完） |
| 回扣理论 | 做完回到 Theory 对应章复盘（衔接回路） |

### 3.3 衔接机制（关键设计）
双区不是并列两份资料，而是**咬合的齿轮**，靠三条钩子衔接：

- **钩子① 讲解→动手（前向）**：Theory 章末尾"动手引子"明确指向 Lab 编号与前置条件；不学完理论不能跳做项目，避免"照抄不会"。
- **钩子② 做完→回扣（反向）**：每个 Lab 末尾"回扣理论"要求学习者用项目经验解释理论（例如"你在 L3 调工具时遇到的参数校验问题，对应 K3 的哪一节？"），把经验上升为概念。
- **钩子③ 主线贯穿（纵向）**：所有 Lab 共用一个 `agent_core` 骨架（最小 loop），新知识以"往骨架上插模块"方式迭代，到大项目时骨架已长成完整系统。学习者每做一个 Lab 都能 `git commit`，看到主线在长大。

> **一句话衔接哲学**：理论给地图，项目给脚印；地图和脚印必须能在同一张纸上对上。

## 四、知识点与学习路径

### 4.1 路径总览（先后顺序与依赖）
路径按 **执行阶段 P0–P8** 划分（与《design_docs/01_整体设计方案》的 Phased Roadmap 完全一致，以该文档为权威口径）。由"单智能体内核"逐步扩展到"工程化与系统"，符合认知由简到繁：

```
P0 脚手架        基础设施：agent_core 最小 Loop、文档模板、仓库结构、术语表
P1 地基          K1 概念与边界 → K2 LLM与提示工程
P2 行动与记忆     K3 工具调用(Function Calling) → K4 上下文与记忆管理
P3 思考          K5 推理范式(CoT/ReAct) → K6 任务规划与分解 → K7 反思与自我修正
P4 协作          K8 多智能体系统与角色协作
P5 知识          K9 检索增强生成(RAG)
P6 工程化        K10 编排与工作流 → K11 评估/可观测性/安全
P7 大项目        Capstone 综合大项目（整合 K1–K11）
P8 评审发布      统稿、一致性走查与发布
```

> 与原"阶段0–6"视图的差异（已对齐 design_docs/01）：① K3/K4 合并为 P2（不再分列两个行动/记忆阶段）；② K8 单独为 P4，**不再与 K9 合并**（K8=多智能体、K9=RAG，性质不同）；③ 阶段总数由 7 改为 9（P0–P8）。

### 4.2 知识点明细表

| 编号 | 知识点 | 核心内容 | 前置依赖 | 执行阶段(P) |
|------|--------|----------|----------|------------|
| K1 | Agent 概念与边界 | 什么是 Agent、与 chatbot/工作流/RPA 的区别、Agent Loop（感知-思考-行动-观察） | 无 | P1 |
| K2 | LLM 基础与提示工程 | Token/上下文窗口、系统提示、Few-shot、结构化输出 | K1 | P1 |
| K3 | 工具调用 | Function Calling 协议、参数校验、工具描述规范、并行/串行调用 | K2 | P2 |
| K4 | 上下文与记忆 | 短期/长期记忆、向量库、摘要压缩、记忆取舍 | K2 | P2 |
| K5 | 推理范式 | CoT、ReAct（Reason+Act）、思维树 | K3 | P3 |
| K6 | 任务规划与分解 | Plan-and-Execute、子任务图、依赖编排 | K5 | P3 |
| K7 | 反思与自我修正 | Self-Reflection、Critic 循环、错误回溯 | K5,K6 | P3 |
| K8 | 多智能体系统 | 角色分工、消息传递、协作/辩论/评审范式、编排者 | K6 | P4 |
| K9 | 检索增强生成 RAG | 切片/嵌入/检索/重排、知识 grounding | K4 | P5 |
| K10 | 编排与工作流 | 图/状态机编排、人机回环、可中断恢复 | K8 | P6 |
| K11 | 评估/可观测/安全 | 轨迹追踪、自动评估、成本控制、越权与幻觉防护 | K10 | P6 |

> **编排逻辑说明**：先让 Agent"会行动"（K3），再让它"记得住"（K4），然后"会想"（K5–K7），再"会协作"（K8），给它"外挂知识"（K9），最后"工程化收口"（K10–K11）。每层都依赖前一层已在主线骨架中跑通。

## 五、配套小项目（Lab Zone）

每个 Lab 对应一个知识点，共用 `agent_core` 骨架，能力目标可验证。

| 编号 | 对应知识点 | 项目主题 | 能力目标 | 验收标准（跑通判定） |
|------|-----------|----------|----------|----------------------|
| L1 | K1 | 最小 Agent Loop 模拟器 | 理解并实现一个"思考→调工具→观察→再思考"的循环 | 给定目标，Agent 能自主循环 ≤N 步并终止，打印轨迹 |
| L2 | K2 | 提示工程练习台 | 设计系统提示、约束结构化输出（JSON） | 输入需求，稳定产出符合 schema 的 JSON |
| L3 | K3 | 工具调用机器人（天气/计算器/搜索） | 编写并注册工具、处理参数校验与失败重试 | 自然语言指令正确触发对应工具并返回结果 |
| L4 | K4 | 有记忆的对话助手 | 实现短期+长期记忆（文件/向量），跨轮召回 | 隔若干轮仍能引用早期信息；长对话不爆窗口 |
| L5 | K5 | ReAct 推理机器人 | 实现 Reason+Act 交替，带 Thought/Action/Observation | 复杂多跳问题能靠工具逐步推理得出答案 |
| L6 | K6 | 任务分解执行器 | 把大任务拆子任务并依依赖顺序执行 | 输入"做一次市场调研"，输出有序执行结果 |
| L7 | K7 | 自审代码机器人 | 生成代码→自我评审→修正的 Critic 循环 | 对含错代码能自检并产出修正版 |
| L8 | K8 | 多智能体协作台（研究员+写手+评审） | 角色消息传递与协作产出 | 三方协作产出一份带评审意见的文稿 |
| L9 | K9 | 本地文档问答助手（RAG） | 切片/嵌入/检索/重排全流程 | 基于给定 PDF/文档准确回答，标注出处 |
| L10 | K10 | 工作流编排器 | 用图串联 L3–L9 模块，支持中断恢复 | 可视化跑通一条多步流程并能从断点续跑 |
| L11 | K11 | 评估与日志面板 | 给 Agent 加轨迹追踪、自动评分、成本统计 | 一次运行产出可读性报告（步骤/耗时/花费/评分） |

> **累计效应**：做到 L11 时，`agent_core` 已具备 工具 / 记忆 / 推理 / 规划 / 反思 / 多智能体 / RAG / 编排 / 评估 九大模块——这正是大项目的零件库。

## 六、综合大项目（Capstone）

### 6.1 整合目标
将 K1–K11 全部整合进**一个真实可交付的端到端系统**，要求学习者证明"能独立设计而非拼装"。

**推荐主题（三选一，按学员背景定）：**
- **A. 深度研究助理（Deep Research Agent）**：输入一个开放研究问题，自主规划→检索多源→多方辩论交叉验证→起草报告→自审修正→产出带引用的长文，全程可观测、可成本控制。
- **B. 个人自动化运营台（Ops Copilot）**：连接邮件/日历/文件/API，按自然语言指令完成跨系统多步任务（如"整理本周客户邮件并生成跟进表"）。
- **C. 代码工程 Agent**：需求→拆任务→写代码→跑测试→自审修复→提 PR 的闭环。

> 下文以 **A（深度研究助理）** 为默认样例展开，B/C 可复用同一骨架替换"工具集与领域知识"。

### 6.2 大项目架构（整合思路）

```
                        用户问题
                            │
                   ┌────────▼────────┐
                   │  Orchestrator    │  ← K10 编排 + K6 规划
                   │  (主控智能体)     │
                   └────────┬────────┘
        ┌──────────┬────────┼──────────┬──────────┐
        ▼          ▼        ▼          ▼          ▼
   Researcher   Critic   Writer    Retriever   Reflector
   (K5/K8)     (K7/K8)  (K8)      (K9)       (K7)
   规划子任务   辩论/挑错  起草报告   检索知识     终稿自审
        │          │        │          │          │
        └──────────┴───┬────┴──────────┘          │
                       ▼                          │
                 Memory & Tools 层  ← K3 工具 + K4 记忆
                       │                          │
                       ▼                          │
                 Eval & Observability ← K11 评估/日志/安全
                       │                          │
                       ▼                          │
                 带引用的最终报告 ─────────────────┘
```

### 6.3 实现思路（分阶段交付，与大项目里程碑对齐）
1. **M0 骨架复用**：直接以 L1–L11 累积的 `agent_core` 为底座，不重写。
2. **M1 模块登记**：把各 Lab 成果注册为可插拔模块（工具/记忆/规划器/反思器/RAG/评估器）。
3. **M2 编排层**：用 K10 的图编排把模块连成"研究流水线"，定义角色节点与消息协议（K8）。
4. **M3 知识接地**：接入 RAG（K9），让检索成为研究员的默认动作。
5. **M4 反思闭环**：Writer 产出后强制过 Critic + Reflector（K7），未达标不交付。
6. **M5 工程化收口**：加 K11 的轨迹追踪、自动评分、成本上限与越权护栏；输出可读报告。
7. **M6 演示与复盘**：用 3 个真实问题端到端跑通，写"设计决策说明书"（证明理解而非拼装）。

### 6.4 大项目验收（整合是否成功）
- 能端到端完成 ≥3 个真实复杂任务，无需人工逐步干预。
- 每个能力模块都能在报告中被"溯源"到对应知识点（证明整合而非黑箱）。
- 具备可观测性：任一次运行可回放完整轨迹、定位失败环节。

## 七、教学节奏与评估建议

| 维度 | 建议 |
|------|------|
| 节奏 | 每周 1 阶段（K1–K2 可合并为第 0 周），Capstone 占 2–3 周 |
| 形式 | 理论自读 + Lab 实操 + 周复盘；双人互审 Lab 代码 |
| 过程评估 | 每个 Lab 的"验收标准"即过关门槛；未完成不进下一阶段 |
| 终评 | Capstone 的"设计决策说明书" + 端到端演示 + 代码走查 |
| 难度护栏 | 每阶段提供"基础版/进阶版"两档 Lab，照顾不同基础 |

## 八、技术栈与前置准备

- **语言**：Python 3.11+
- **LLM 接入**：开放兼容接口（如 OpenAI / 兼容端点），统一封装在 `agent_core` 的 `LLMClient`
- **记忆**：向量库（如 FAISS / Chroma，本地优先，零云依赖即可跑）
- **编排**：先用纯 Python 实现图/状态机（K10 前不引入重框架），后续可选 LangGraph 等对照学习
- **RAG**：嵌入模型 + 切片/重排（K9 引入）
- **评估**：自写轨迹日志记录 + 简单自动评分脚本（K11）
- **工程**：git 做主线成长记录；每个 Lab 一个 commit；Capstone 一个独立分支
