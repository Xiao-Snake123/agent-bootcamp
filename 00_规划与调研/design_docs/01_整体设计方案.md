# Agent 系统学习教学大项目 · 整体设计方案

> 本文档是总纲，定义"如何从整体架构到具体细节逐步设计该项目"。
> 配套详文：《02_文字教学模块设计文档.md》《03_项目教学模块设计文档.md》。
> 前置：本目录上级的 `Agent学习教学项目规划.md`（项目规划书）。

---

## 1. 设计目标与定位

**一句话目标**：把"懂 Agent 原理"与"会造 Agent 系统"绑成一条可落地的学习链路，最终用综合大项目把全部知识点整合贯通。

三大交付物：
- **理论区（可懂）**：建立 Agent 统一心智模型，回答"为什么 / 是什么 / 怎么想"。
- **项目区（会造）**：每知识点对应一个可运行项目，回答"怎么造 / 跑起来"。
- **大项目（能整合）**：端到端系统，证明"能独立设计而非拼装"。

---

## 2. 设计哲学（整体思路）

四条原则贯穿全程：

1. **概念先行，动手印证**：每个理论点必须对应一个能跑的项目。先给地图，再踩脚印；地图与脚印必须在同一张纸上对上。
2. **由点到面，主线贯穿**：以 `agent_core` 最小骨架为种子，每个新知识 = 往骨架插一个模块。学习者每做一个 Lab 都能看到"系统长大"。
3. **双区咬合，反向回扣**：理论→项目（前向钩子）、项目→理论（反向钩子），避免"照抄不会 / 学完就忘"。
4. **生产导向，渐进工程化**：从玩具 Demo 起步，逐步逼近生产级（评测 / 可观测 / 安全 / 成本）。

---

## 3. 总体架构（双区 + 主线 + 大项目）

```
中央学习主线(Spine): agent_core 骨架，从"最小Loop"逐步长成"完整系统"
        │                                  │
  文字教学区(Theory)  ──钩子①讲解→动手──▶  项目教学区(Lab)
        │  ◀──钩子②做完→回扣理论──          │
        └──────────────┬───────────────────┘
                  综合大项目(Capstone): 整合 K1–K11
```

- **Spine（主线）**：不是独立内容，而是一条贯穿线索——所有 Lab 共用 `agent_core` 骨架，新知识以"插模块"方式迭代。
- **Theory Zone**：按学习路径拆解的概念章节（固定 7 节结构，见《02》）。
- **Lab Zone**：与理论一一对应的动手项目（固定 6 节结构，见《03》）。
- **Capstone**：收口，把全部模块组装成端到端系统。

## 4. 技术栈与工程基线

| 维度 | 选型 | 说明 |
|------|------|------|
| 语言 | Python 3.11+ | 唯一教学语言，降低认知负担 |
| LLM 接入 | 兼容端点封装（`LLMClient`） | OpenAI 格式统一；支持本地模型（Ollama）兜底 |
| 记忆/向量 | Chroma / FAISS（本地优先） | 零云依赖即可跑；可选 Milvus |
| 编排 | 先纯 Python 图/状态机 | K10 前不引入重框架；之后可选 LangGraph 对照 |
| RAG | embedding + 切片/重排 | K9 引入 |
| 评估 | 自写轨迹日志 + 自动评分 | K11 引入 |
| 工程 | git + pytest + markdown | 每 Lab 一 commit；验收靠测试+跑通 |

**工程基线原则**：本地优先、密钥走 `.env`、所有 LLM 调用带 token 计数与成本上限。

## 5. 分阶段实施步骤（Phased Roadmap）

按"地基→行动→记忆→思考→协作→知识→工程化→大项目→发布"推进。每阶段遵循"写章→写 Lab→自检一致性→提交"四步。

| 阶段 | 范围 | 阶段目标 | 关键产出 | 里程碑验收 | 周期建议 |
|------|------|----------|----------|------------|----------|
| **P0 脚手架** | 基础设施 | 建立可复用的骨架与规范 | `agent_core` 最小 Loop、文档模板、仓库结构、术语表、写作规范 | 骨架可跑通一个 mock 工具循环；模板被评审通过 | 3–5 天 |
| **P1 地基** | K1–K2 | 建立 Agent 心智模型与提示基础 | 理论章 K1/K2 + Lab L1/L2 | L1 能自主循环并终止；L2 稳定产出 JSON | 1 周 |
| **P2 行动与记忆** | K3–K4 | 让 Agent 会行动、记得住 | K3/K4 + L3/L4 | L3 自然语言触发正确工具；L4 跨轮召回且不爆窗 | 1 周 |
| **P3 思考** | K5–K7 | 让 Agent 会推理/规划/反思 | K5/K6/K7 + L5/L6/L7 | L5 多跳靠工具得答；L6 拆任务有序执行；L7 自检修正 | 1.5 周 |
| **P4 协作** | K8 | 多智能体角色协作 | K8 + L8 | L8 三角色协作产出带评审文稿 | 1 周 |
| **P5 知识** | K9 | 外挂知识 RAG | K9 + L9 | L9 基于给定文档准确回答并标注出处 | 1 周 |
| **P6 工程化** | K10–K11 | 编排与评估/安全收口 | K10/K11 + L10/L11 | L10 图编排可中断恢复；L11 产出评估报告 | 1 周 |
| **P7 大项目** | K1–K11 整合 | 端到端系统 | Capstone 代码 + 设计决策说明书 + 演示 | 端到端跑通 ≥3 真实任务；模块可溯源；可观测回放 | 2–3 周 |
| **P8 评审发布** | 统稿 | 一致性走查与发布 | 双区对齐检查表、配套答案/评分、发布包 | 全 11 章与 11 Lab 逐条对齐；样式统一 | 3–5 天 |

**每个阶段输入**：前置章节/Lab 已完成且验收通过。
**每个阶段产出**：理论章文档 + Lab 代码与 README + 一致性自检记录 + 一个 git 提交/标签。

---

## 6. 质量保障与一致性机制

- **双区一致性检查表**（每章理论点 ↔ 对应 Lab 能力目标 逐条对应）：缺一项不进下一阶段。
- **理论章评审清单**：七节齐全、目标可验证、有原理有图/伪代码、有陷阱、有自检、有动手引子。
- **Lab 验收清单**：能跑通、有 README、有 reflection 回扣理论、有 ≥1 个 pytest 验收测试。
- **术语表集中**：`glossary.md` 统一名词，禁止同词多义。
- **版本与变更**：每阶段打 git tag（如 `phase-1`）；框架升级只改适配层，不动骨架接口。

---

## 7. 风险与对策

| 风险 | 表现 | 对策 |
|------|------|------|
| 理论太抽象 | 学完不会用 | 每个原理配可运行伪代码/最小示例；前向钩子强制先学 |
| Lab 抄答案 | 照抄不会 | 参考实现只给要点不给全码；要求写 reflection 回扣 |
| 框架版本漂移 | 代码跑不起来 | `agent_core` 抽象接口稳定；框架仅作可选对照层 |
| 大项目拼装 | 不懂设计 | 要求"设计决策说明书"把每个模块溯源到知识点 |
| 成本/密钥失控 | 超支/泄密 | 本地模型可选、密钥走 env、LLMClient 加成本上限 |

---

## 8. 如何使用本套文档指导开发

1. **先 P0 脚手架**：落地 `agent_core` 与文档模板，再批量铺开。
2. **按阶段逐对产出**：每阶段 = 一篇理论章 + 一个 Lab，走"写章→写 Lab→自检一致性→提交"四步。
3. **遇到知识点细节争议**：查术语表与《02》章节规划；遇到工程实现争议：查《03》骨架与 Lab 规范。
4. **收口做大项目**：直接复用 L1–L11 累积的 `agent_core` 零件库，按《03》Capstone 设计组装。

> 下一步建议：先完成 P0 脚手架（最小 `agent_core` + 本章模板），再产出 K1+L1 作为首个样板，验证双区咬合手感，之后按 Roadmap 铺开。
