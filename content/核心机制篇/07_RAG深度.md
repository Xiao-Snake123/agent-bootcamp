# 第 7 章 RAG 深度（检索增强生成）

> 难度：★★★★☆ ｜ 前置：第 2、3 章 ｜ 对应旧 K8

## 7.1 RAG 在 Agent 里的位置
RAG 让模型**基于外部语料**回答，而不是只靠参数记忆。在 Agent 中，RAG 既可作为独立工具（"搜一下知识库"），也可在上下文工程层自动检索注入（第 3 章 3.6）。本章聚焦工程细节与失败模式。

## 7.2 管线总览
```
语料 → 切分(chunk) → 向量化(embedding) → 入库(vector store)
查询 → 向量检索(top-k) → [可选 hybrid/rerank] → 拼进上下文 → 生成
```

## 7.3 切分策略（chunking）
- **固定大小 + 重叠**：简单，但易切断语义（一句话跨两块）。
- **语义切分**：按段落/标题/句子边界切，保留结构。
- **大小**：太小→检索噪声多；太大→单块塞不下或引入无关内容。经验 512~1024 token + 128 重叠。
- **元数据切分**：保留来源/章节/时间，便于过滤（如"只看 2025 年文档"）。

## 7.4 Embedding 选型
- 通用：`text-embedding-3-small`（OpenAI）、`bge-m3`/`gte`（开源多语言）。
- 领域适配：法律/医学等可用领域微调嵌入。
- 检索语言匹配：中文语料优先多语言或中文嵌入模型。
- 成本：嵌入是一次性成本，但语料更新需重嵌。

## 7.5 Hybrid 检索（向量 + 关键词）
纯向量检索对"精确实体/专名"弱（如错误码 `E1024`）。Hybrid = 向量召回 ∪ BM25 关键词召回，再合并：
```python
hits = bm25(query, k=20) ∪ vector_search(query, k=20)
ranked = reciprocal_rank_fusion(hits)   # RRF 融合
```
专名、ID、罕见词场景 hybrid 显著提升召回。

## 7.6 Rerank
召回 top-20 后用交叉编码器 reranker（如 Cohere Rerank、bge-reranker）精排到 top-5，提升"最相关块"命中率。代价是多一次模型调用，但大幅改善答案质量。

## 7.7 查询改写
用户问题口语化/多跳，直接向量化效果差。先让 LLM 把查询改写成"检索友好"形式（或分解成多个子查询分别检索再合并）。

## 7.8 评测与失败模式
- **评测指标**：检索 recall（相关块是否在前 k）、答案 faithfulness（是否基于检索内容、有无编造）、答案相关性。
- **失败模式**：
  - 检索不到（chunk 不当/嵌入不匹配/查询太泛）。
  - 上下文污染（塞了不相关块 → 模型被带偏）。
  - Lost-in-the-middle（关键块在第 2 位被忽略，见第 3 章）。

## 7.9 最小实现（hybrid + rerank 思路）
```python
def rag_answer(q):
    cand = bm25(q, 20) | embed_search(q, 20)
    top = rerank(q, cand, top_k=5)
    ctx = "\n---\n".join(t.text for t in top)
    return llm(f"基于以下资料回答：\n{ctx}\n\n问题：{q}")
```

## 7.10 论文与延伸
- Self-RAG（arXiv:2310.11511）：让模型**自适应**决定何时检索、何时反思，缓解过度/不足检索。
- LlamaIndex 文档：检索/rerank/评估的完整实现参考。

## 7.11 面试考点
1. **chunk size 怎么选？** 答：依语料结构，512~1024+重叠，保留语义边界与元数据；用评测反调。
2. **为什么需要 rerank？** 答：向量召回 top-k 含噪声，reranker 用交叉编码精排，提升最相关块命中。
3. **RAG 答非所问如何排查？** 答：先看检索 recall（相关块是否在候选），再看上下文污染/排序，最后看生成是否忠实。

## 7.12 常见坑
- **embedding 与查询语义不匹配**（如中英混用）→ 召回差。
- **未做去重/未过滤** → 重复块占满窗口、引入噪声。
- **只信向量检索** → 专名/ID 类查询失效，需 hybrid。
