# 第 2 章 工具系统

> 难度：★★★☆☆ ｜ 前置：第 1 章 ReAct、了解 JSON Schema ｜ 对应旧 K2/K9

## 2.1 为什么需要工具系统
ReAct 里工具是"硬编码一个 dict 分发"（第 1 章 demo）。真实 Agent 要接几十个工具（搜索、SQL、代码执行、内部 API），必须有**声明—路由—调用—容错—结果回注**的标准化管线。工具系统就是把"模型说要调什么"安全地变成"真实世界里发生了什么"。

## 2.2 工具声明：JSON Schema 是第一公民
工具不止是函数，而是一段**机器可读的契约**：
```json
{
  "name": "sql_query",
  "description": "对只读副本执行 SELECT 查询，返回前 100 行。禁止写操作。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "标准 SQL SELECT 语句"},
      "timeout_ms": {"type": "integer", "default": 3000}
    },
    "required": ["query"]
  }
}
```
**经验**：`description` 比代码还重要——模型靠它选工具、靠参数 `description` 填参。模糊描述（"执行查询"）会导致选错工具或参数错填。

## 2.3 工具路由与选择
- 显式路由：模型直接 `tool_calls` 指定 name（主流）。
- 隐式路由：用一个"路由器"模型先把用户意图映射到候选工具子集，再交给主模型——降低长工具列表的噪声（工具过多会撑爆上下文、降低选择准确率）。
- 工具太多时的策略：按命名空间分组、用 embedding 检索相关工具、或用"工具检索器"。

## 2.4 调用执行：校验、并行、聚合
```python
def execute_tool(call):
    fn = REGISTRY[call.name]
    # 1) 参数校验（pydantic / jsonschema）
    args = ToolSchema[call.name].model_validate(call.args)
    # 2) 执行（支持并行）
    return fn(**args)

# 并行：模型一次返回多个 tool_calls 时并发执行
observations = parallel_map(execute_tool, decision.tool_calls)
```
要点：模型可一次返回**多个** `tool_calls`，应并发执行再聚合，避免串行拖慢；但写操作工具必须串行且带事务/幂等。

## 2.5 容错：重试 / 熔断 / 超时 / HITL
- **超时**：每个工具必须有 `timeout`，否则一个挂起工具卡死整个循环（呼应第 12 章）。
- **重试**：对瞬时错误（网络）指数退避重试；对参数错误**不重试**，转成 Observation 让模型改参。
- **熔断**：某工具连续失败，临时禁用并通知模型换方案。
- **Human-in-the-loop**：高风险工具（发邮件、删数据、支付）应在执行前暂停，等人工确认——这是 `tool` 节点插入人工审批的天然位置（见第 9 章 checkpoint）。

## 2.6 结果回注
工具结果（无论成功/异常）都序列化为 Observation 回注上下文。异常要包成可阅读文本（如 `"error: timeout after 3000ms"`），**绝不能抛异常中断循环**。大结果要截断/摘要（避免撑爆窗口，见第 3 章）。

## 2.7 工业实现差异
- **OpenAI**：`tools` 参数 + `tool_calls`（函数调用对象），原生支持并行、支持 `tool_choice` 强制调用；结果用 `role: tool` + `tool_call_id` 回注。
- **Anthropic**：`tools` + `tool_use` 内容块；结果用 `tool_result` 块；不支持把工具结果伪装成普通文本。
- **开源（LangChain Tool / MCP）**：把工具抽象成统一接口，MCP 进一步把"工具定义—调用—传输"标准化为协议（见第 8 章）。

## 2.8 论文与延伸
- Toolformer（arXiv:2302.04761）：证明让 LM **自己决定**何时/如何调 API 能提升下游任务，是工具调用的训练侧奠基。

## 2.9 面试考点
1. **模型返回的 tool_calls 不可信（参数缺字段/类型错）怎么办？** 答：先按 Schema 校验，失败转成 Observation 让模型自我修正；不盲目执行。
2. **多工具并行如何合并结果？** 答：并发执行、用 `tool_call_id` 对齐；写操作需串行+幂等。
3. **如何防止模型反复调同一个失败工具？** 答：熔断 + 在 Observation 中明确告知"该工具暂不可用，请换方案"。

## 2.10 常见坑
- **工具 description 潦草** → 模型选错工具或填错参，是最常见隐性 bug。
- **工具无超时/无权限边界** → 轻则卡死，重则越权执行（如误删库），呼应第 11 章。
- **把大结果整段塞回上下文** → 撑爆窗口、抬高成本（应在回注前截断/摘要）。
