# 第 12 章 生产化 SRE（从 demo 到稳定服务）

> 难度：★★★★★ ｜ 前置：第 1–11 章全部 ｜ 综合章

## 12.1 为什么 demo 不等于生产
本地跑通只是开始。生产要面对：并发、超时、模型/工具故障、成本失控、延迟抖动、可观测与告警。本章把前面各章的"坑"收敛成运维清单。

## 12.2 部署形态
- **在线服务**：FastAPI/gRPC 暴露 `/chat`、`/run_agent`，供前端/问答助手调用（也是站内求职助手的后端形态）。
- **流式输出**：用 SSE/WebSocket 把 token 逐步返回，避免用户等完整生成（长轨迹必须流式）。
- **异步任务**：长 Agent 任务用队列（Celery/Worker），前端轮询/回调。

## 12.3 并发与限流
- LLM 调用有速率限制（RPM/TPM），需客户端限流 + 服务端配额。
- 工具并发要受控（第 2 章并行调用 but 限总数），避免打爆下游 API。
- 用户级/租户级配额，防止单用户拖垮全局。

## 12.4 缓存：语义缓存
对"相同/近似问题"缓存答案，大幅提升命中、降成本、降延迟：
```python
key = embed(normalize(question))
if cache.get(key): return cache[key]      # 语义相似即命中
ans = agent.run(question); cache.set(key, ans)
```
注意：有副作用/实时性的查询不能缓存。

## 12.5 降级（Degradation）
- **模型降级**：主模型超时/限流 → 切更小更快模型兜底（质量降、可用性保）。
- **工具降级**：某工具熔断（第 2 章）→ 通知 Agent 换方案或返回"暂不可用"。
- **整体降级**：依赖全挂 → 返回友好提示而非雪崩。

## 12.6 监控与告警
- 指标：成功率、P50/P95 延迟、token 成本、工具错误率、注入拦截数。
- 链路追踪：每次运行的轨迹（第 10 章）关联 trace_id，便于排障。
- 告警：成本突变、错误率突增、注入攻击频发。

## 12.7 成本治理
- 稳定前缀命中 KV 缓存（第 3 章）。
- 语义缓存（12.4）、摘要压缩（第 3 章）降 token。
- 模型分级（贵模型只用于难步骤，简单步骤用小模型）。

## 12.9 面试考点
1. **如何做语义缓存提升命中？** 答：问题归一化+嵌入相似匹配，近似问题复用答案；副作用/实时查询不缓存。
2. **Agent 服务如何限流与降级？** 答：LLM RPM/TPM 客户端限流+租户配额；模型/工具降级兜底，保可用。
3. **为什么 Agent 比普通 LLM 服务更易雪崩？** 答：多步+多工具调用，一个下游慢/挂会级联放大；需超时、熔断、降级隔离。

## 12.10 常见坑
- **无超时** → 一个卡住的工具/模型调用拖垮整请求，级联雪崩。
- **忽视流式下的错误传播** → 已发出部分结果后后端报错，前端状态不一致。
- **无成本护栏** → 反思循环（第 5 章）+ 长轨迹把账单烧爆。
