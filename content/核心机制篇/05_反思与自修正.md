# 第 5 章 反思与自修正（Reflexion）

> 难度：★★★☆☆ ｜ 前置：第 1、4 章 ｜ 对应旧 K6

## 5.1 为什么需要反思
ReAct 只看"眼前 Observation"，不会"总结我刚才哪里错了"。很多任务需要 Agent **基于结果自我批评、调整策略**——例如代码生成跑测试失败后要改，而不是换个随机写法再错一次。

## 5.2 Reflexion 的核心结构
Reflexion 在 ReAct 循环外增加**反思记忆**：
```
loop:
    行动 → 观察（含环境反馈，如测试用例结果）
    若失败/未达标：
        反思 = LLM(轨迹 + 失败原因)   # 产出"我哪里错了、下次注意"
        把 反思 写入 reflection memory
    下一轮把 reflection 注入上下文，引导避坑
```
关键点：反思是**写给人/模型自己看的文字经验**，不是梯度更新（verbal reinforcement）。

## 5.3 反思的来源：环境反馈
- 客观反馈：单元测试失败、API 返回错误码、检索为空。
- 主观反馈：用一个"批评者"模型评估输出质量（LLM-as-critic）。
- 对比反馈：与参考答案/基线比对。

## 5.4 最小实现
```python
reflections = []
def act_with_reflection(goal, max_tries=3):
    for i in range(max_tries):
        traj = build_trajectory(goal, reflections)
        dec = llm(traj)
        obs = execute(dec)
        if obs.ok:
            return dec.final_answer
        # 失败 → 生成反思
        reflections.append(llm.reflect(traj + f"\n失败原因:{obs.error}"))
    return "重试耗尽"
```
陷阱：反思无限循环（见 5.8）。

## 5.5 与第 4 章规划的关系
反思可用于**重规划触发器**：当反思指出"计划本身有误"，调用第 4 章的 `replan` 而非仅改一步。

## 5.6 验证器（Verifier）
比泛化反思更稳的做法：用一个确定性验证器（测试/类型检查/规则）判定成功，反思只解释"为何未过验证"。避免"自我感觉良好"的伪反思。

## 5.7 论文与延伸
- Reflexion: Language Agents with Verbal Reinforcement Learning（arXiv:2303.11366）。
- CRITIC：用外部工具（如代码执行、知识库）批评并修正。
- 延伸：第 10 章把"反思质量"纳入评测；第 12 章限制反思次数控成本。

## 5.8 面试考点
1. **反思会不会陷入自我循环？** 答：会。必须设最大重试次数、且反思要基于客观验证器而非纯主观，否则烧钱且无进展。
2. **如何区分"真错误"与"风格差异"？** 答：用确定性验证器（测试/规则）定义对错，反思只解释验证失败原因，不评判风格。
3. **Reflexion 与微调（fine-tune）的区别？** 答：Reflexion 不改权重、靠文字经验注入上下文，零训练成本、可解释；微调改权重但需数据管线。

## 5.9 常见坑
- **反思无外部真值** → 模型胡乱自我否定或自我安慰，循环无效。
- **无限重试** → 不设上限，成本失控（呼应第 10/12 章成本护栏）。
- **反思写得太泛** → "下次小心"这种无效反思，对后续无指导意义。
