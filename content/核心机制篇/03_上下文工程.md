# 第 3 章 上下文工程（Context Engineering）

> 难度：★★★☆☆ ｜ 前置：第 1–2 章 ｜ 对应旧 K3/K4

## 3.1 为什么上下文工程是 Agent 的"内存管理"
LLM 没有持久记忆，它"知道"的只有**当前这一次请求里塞进上下文窗口的内容**。Agent 跑多步后，上下文里混杂 system / 历史消息 / 工具结果 / 反思，如何组织这段内容直接决定效果、延迟与成本。上下文工程 = 决定"在每一步把什么放进窗口、以什么顺序、保留多久"。

## 3.2 消息的角色与组织
- `system`：固定的人设/规则/工具说明——尽量精简且稳定（影响 KV 缓存命中）。
- `user` / `assistant`：对话与模型产出。
- `tool` / `tool_result`：工具结果回注（第 2 章）。
- **顺序即注意力**：越靠后越被重视（recency bias）；关键约束放 system 末尾或最近一条 user 消息。

## 3.3 KV 缓存：被忽视的成本杠杆
主流推理服务对**前缀相同的上下文**做 KV 缓存复用。若 system + 长工具定义固定不变，应放在最前面并保持不变，否则每步都重新计费+计算。
```python
# 好：稳定前缀（system + 工具定义）放最前、不随步数变动
messages = [SYSTEM, TOOL_DEFS, *dynamic_history]
# 差：每步把 system 重新拼在变动内容之后 → 缓存全失效
```

## 3.4 摘要压缩（应对长轨迹）
当轨迹超过窗口 X% 时，把早期 (thought/action/observation) 压缩成一段摘要替换：
- 用模型生成摘要（"前 N 步：已查 A、算出 B，当前目标 C"）。
- 或丢弃低价值 Observation（只留结论）。
- **保留关键点**：已确认的事实、未完成的子目标、约束。

## 3.5 短期记忆 vs 长期记忆
- **短期**：当前上下文窗口内的消息（易溢出，需 3.4 压缩）。
- **长期**：外部存储（向量库 / KV / 文件），按需检索回注。典型实现：
```python
class Memory:
    def retrieve(self, query, k=5): ...   # 语义检索相关记忆
    def append(self, fact): ...            # 把新事实写入长期存储
```
注意：长期记忆检索 ≠ RAG（第 7 章）——记忆是**Agent 自己产生的过程知识**，RAG 是**外部语料**。

## 3.6 把 RAG 当作上下文的一部分
检索到的文档不是"答案"，而是被拼进上下文让模型基于它推理（第 7 章详述）。上下文工程要决定：检索多少、放哪（system 之后？user 之前？）、是否标注来源。

## 3.7 上下文优先级策略
当窗口紧张，优先级通常为：系统约束 > 当前目标 > 最近 observation > 长期相关记忆 > 早期历史摘要。可用"预算分配"思路：给每类内容设定最大 token 配额。

## 3.8 工业实践
- Anthropic《Context Engineering for AI Agents》强调"少即是多"、稳定前缀、按需检索。
- 开源：LangGraph 用 `state` 显式管理上下文；MemGPT 风格把内存分层（主上下文 + 外部存储 + 自动换页）。

## 3.9 面试考点
1. **上下文溢出有哪些策略？** 答：摘要压缩、长期记忆外置+检索、截断低价值内容、提高缓存命中减少重算。
2. **长期记忆检索与 RAG 的区别？** 答：记忆是 Agent 自我产生的过程知识；RAG 是外部静态语料。二者可共用向量库但语义不同。
3. **如何降低 token 成本又不影响效果？** 答：稳定前缀命中 KV 缓存、压缩历史、按需检索而非全量塞入。

## 3.10 常见坑
- **把全部历史无脑塞回** → 窗口溢出或成本爆炸。
- **忽略缓存命中** → system/工具定义每步微变，缓存失效，延迟和成本翻倍。
- **摘要丢失关键约束** → 压缩时把"禁止项"删了，Agent 后续越界。
