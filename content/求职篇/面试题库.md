# 求职篇 · 面试题库

按《核心机制篇》12 章组织，每章含 4 类题：概念辨析、系统设计、代码/实现、故障排查。答案要点可直接用于面试回答，完整推导见对应章节。

## 第 1 章 推理-行动循环 ReAct
- **概念**：ReAct 是什么？为什么比纯思维链更适合 Agent？要点：交错 Thought/Action/Observation；让模型基于环境反馈决策，避免"闭门造车"式幻觉规划；可观测、可中断。
- **设计**：如何防止 ReAct 死循环？要点：硬上限 max_steps；目标达成检测（模型输出 FINISH）；循环检测（相同 action+observation 重复 N 次即终止）；引入反思节点。
- **代码**：手写最小 ReAct loop。要点：while step<max: thought,action=LLM(...); obs=tool(action); 若 action=FINISH 退出；把 thought/action/obs 回填历史。
- **故障**：Agent 反复调用同一工具且输出不变，怎么排查？要点：检查 Observation 是否真变化；工具是否幂等；加 max_steps 与去重；让模型显式判断"已完成"。

## 第 2 章 工具系统
- **概念**：Function Calling 与直接让模型输出 JSON 调工具有何区别？要点：FC 由推理引擎结构化解析、自带 schema 校验与重试；裸 JSON 易格式错、难校验。
- **设计**：工具很多（上百个）时如何做路由与选择？要点：先检索/分类再精选 top-k 工具进上下文；用 embedding 召回相关工具；分层（基础工具常驻，领域工具按需加载）。
- **代码**：给一个工具声明（JSON Schema）并说明 required/type 约束。要点：name/description 影响检索与选择；参数用 JSON Schema；enum 限制取值。
- **故障**：模型传了不存在的参数或类型错误。要点：严格 schema 校验 + 报错回填让其重试；限制重试次数；对关键工具加 HITL。

## 第 3 章 上下文工程
- **概念**：上下文工程与 prompt 工程区别？要点：前者管理"跨多轮的完整上下文结构"（系统提示/记忆/工具结果/压缩），后者偏单条指令措辞。
- **设计**：长任务上下文溢出怎么办？要点：KV 缓存复用前缀；摘要压缩旧轮次；分级记忆（工作/短期/长期）；把大结果存外部以引用代替内联。
- **代码**：说明 KV 缓存如何降低延迟与成本。要点：稳定前缀命中缓存避免重算；把不变系统提示/工具定义放在前缀；避免在前缀中插入易变内容。
- **故障**：Agent 后期"忘了"早期约束。要点：约束进稳定前缀（走缓存）；关键约束摘要进每轮；用长期记忆持久化。

## 第 4 章 规划与分解
- **概念**：Plan-and-Execute 与 ReAct 区别？要点：前者先生成完整计划再逐步执行（全局性），后者边走边决策（适应性）；计划可重规划。
- **设计**：如何把"写一份带图表的调研报告"分解为可执行子任务？要点：建 DAG；识别并行与依赖；每个子任务有明确产出与验收。
- **代码**：任务 DAG 如何用拓扑排序执行？要点：入度为 0 才可执行；完成一个节点更新下游入度；失败触发重规划而非整体重来。
- **故障**：计划执行到一半目标变了。要点：保留已完成状态；做增量重规划；用 checkpoint 恢复。

## 第 5 章 反思与自修正
- **概念**：Reflexion 是什么？要点：让 Agent 基于环境反馈/自我批评生成反思文本，存入记忆指导后续尝试，避免重复犯错。
- **设计**：何时触发反思？要点：任务失败、步数达上限、结果不满足验收、或重复循环时；反思要具体（哪步错、为什么、下次怎么做）。
- **代码**：反思循环骨架。要点：try → 环境反馈 → LLM 生成反思 → 写入记忆 → 下次携带反思重试。
- **故障**：反思变成"自我安慰"无实质改进。要点：反思锚定客观反馈（测试/分数），而非主观；限制重试次数防无限循环。

## 第 6 章 多 Agent 协作
- **概念**：多 Agent 与单 Agent+工具的区别与取舍？要点：多 Agent 用于职责/上下文隔离与并行；代价是通信开销、一致性、死锁风险；不是越多越好。
- **设计**：设计一个"研究员+工程师"双 Agent 协作流程。要点：明确角色协议与消息格式；Orchestrator 分发与汇总；定义终止与升级条件。
- **代码**：如何避免多 Agent 死锁？要点：消息总线 + 超时；每轮有最大回合；引入仲裁/Orchestrator 打破僵局；资源共享用锁或单一所有者。
- **故障**：两个 Agent 互相推诿任务。要点：责任边界写清；Orchestrator 做最终裁决；用目标完成信号终止。

## 第 7 章 RAG 深度
- **概念**：RAG 为什么需要 hybrid 检索？要点：BM25 擅长专名/精确匹配，向量擅长语义；融合兼顾召回率与语义。
- **设计**：设计一套文档问答 RAG 管线。要点：chunk 策略（大小/重叠）→ embedding → 存储 → hybrid 召回 → rerank → 拼上下文 → 生成；评估各段质量。
- **代码**：chunk 大小如何选？要点：按语义边界（段落/标题）切；重叠保留上下文；太大稀释、太小丢上下文；用检索评估反调。
- **故障**：检索到的内容正确但生成答非所问。要点：检查拼装（是否混入无关块）、rerank 是否把相关块排后面、prompt 是否要求"仅基于资料"；加引用约束。

## 第 8 章 能力扩展 MCP/FC/Skill
- **概念**：MCP、Function Calling、Skill 三者关系？要点：FC 是模型调工具的原语；MCP 是工具/数据源的开放协议（标准化接入）；Skill 是更高层可复用能力包（多步流程+资源）。
- **设计**：何时用 MCP 而非硬编码工具？要点：多客户端复用、需要标准鉴权/发现、跨语言接入外部系统时用 MCP；简单内部工具可直接 FC。
- **代码**：MCP 客户端连一个 local server 的最小步骤。要点：启动 server（stdio/http）→ client connect → list tools → call tool → 拿结果。
- **故障**：MCP 工具调用超时/崩溃影响主流程。要点：工具沙箱隔离；超时与熔断；失败兜底不阻断主 Agent。

## 第 9 章 编排与框架
- **概念**：为什么 Agent 需要状态机/图编排而非裸循环？要点：显式状态便于中断恢复、可观测、分支与回退；适合长任务与多人协作。
- **设计**：设计一个可恢复的长任务编排。要点：节点=状态；边=转移；checkpoint 持久化；中断后可从节点恢复；保证动作幂等。
- **代码**：checkpoint 如何保证重启不重复副作用？要点：每步开始前写 checkpoint；恢复时跳过已完成节点；外部调用幂等（带 idempotency key）。
- **故障**：重放导致重复发消息。要点：副作用操作幂等化；checkpoint 在副作用提交后更新；用唯一任务 id 去重。

## 第 10 章 评测与可观测
- **概念**：为什么 RAG/Agent 不能只靠"看着还行"？要点：非确定性、长链路、难回归；需离线评测 + 在线监控双轨。
- **设计**：如何评测一个 RAG 回答质量？要点：检索召回率/精度、答案 faithfulness（是否忠于资料）、答案相关性；用 LLM-as-Judge + 人工抽检。
- **代码**：LLM-as-Judge 怎么避免评委模型偏心？要点：给评委明确 rubric；多评委投票；与人工标注对齐校准；记录轨迹供复盘。
- **故障**：线上回答崩但测试集全过。要点：监控真实轨迹与用户反馈；埋点关键节点；做 failure replay 回归。

## 第 11 章 安全与合规
- **概念**：Agent 面临哪些特有安全风险？要点：提示注入（间接注入经工具结果）、数据泄露（敏感上下文外发）、权限过大、不可控外部调用。
- **设计**：如何防御间接提示注入？要点：工具结果视为不可信数据（与指令隔离）；对外部内容做标记/沙箱；关键动作 HITL；输出过滤。
- **代码**：最小权限如何落地？要点：每个工具最小 scope；调用需显式授权；敏感操作二次确认；审计日志。
- **故障**：Agent 被诱导把系统提示泄露给用户。要点：系统提示与用户可见内容分离；禁止模型引用/输出系统提示；注入检测。

## 第 12 章 生产化 SRE
- **概念**：Demo 到生产最大的差距在哪？要点：流式、并发限流、降级、可观测、成本控制、失败恢复与上线清单。
- **设计**：如何给 Agent 服务做限流与降级？要点：按用户/全局限流；依赖超时与熔断；LLM 不可用时降级到缓存/模板；语义缓存命中直接返回。
- **代码**：语义缓存怎么提升命中与省成本？要点：对 query 做归一化+embedding；相似度超阈值直接复用历史答案；注意私密数据隔离。
- **故障**：高峰期 p99 延迟飙升。要点：查 LLM 限速/排队、KV 缓存命中率、工具调用耗时；加并发控制与超时；用流式改善体感。
