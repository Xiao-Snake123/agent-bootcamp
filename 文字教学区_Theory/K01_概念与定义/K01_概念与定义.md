# K01 Agent 概念与定义（对应执行阶段 P1）

> 本章建立 Agent 的统一心智模型：它不是一个函数调用，而是一个"感知—思考—行动—观察"的闭环。学完立刻进入 `项目教学区_Labs/L01_最小AgentLoop/` 动手印证。

## 一、学习目标
学完你能：
1. 用自己的话定义什么是 Agent；
2. 说清 Agent 与普通脚本、聊天机器人、RPA 的区别与边界；
3. 描述 Agent Loop（感知—思考—行动—观察）四个环节，并指出哪一环由模型决定、哪一环由代码执行；
4. 运行 L1 的最小 Agent Loop 并读懂轨迹（Trajectory）。

## 二、核心概念
- **Agent（智能体）**：在环境中**自主感知、思考、行动以达成目标**的软件系统。核心特征是"闭环"——不是一次性函数调用，而是"看结果→再决定→再行动"的循环。
- **与脚本的区别**：脚本是固定的 `if/else` 流程；Agent 的下一步行动由模型在运行时**动态决定**。
- **与 chatbot 的区别**：chatbot 多半只生成文本；Agent 能"动手"调用工具改变外部状态（查天气、算数、写文件）。
- **与 RPA 的区别**：RPA 按录制好的固定步骤操作界面；Agent 能应对未见过的情形、做决策。
- **Agent Loop**：感知(Perceive) → 思考(Think/Reason) → 行动(Act) → 观察(Observe) → 回到思考，直到满足终止条件（给出最终答案，或触达步数上限）。

## 三、工作原理
最小循环伪代码：

```
目标 = 用户输入
循环（最多 N 步）：
    思考 = 模型(历史 + 目标)        # 决定下一步：调哪个工具，还是直接回答
    如果 思考 是"最终答案"：返回并终止
    否则：执行 思考.动作(工具) → 得到 观察
    把 观察 加入历史
返回 最终答案
```

关键在于"思考"这一步由模型**动态产出决策**，而"行动"由你的代码**真实执行**，"观察"再喂回模型，形成闭环。L1 用 `MockLLMClient` 这个离线决策器，先把这条链路跑通，再谈接真模型。

## 四、主流方案
- **ReAct（Reason + Act）**：交替生成 Thought 与 Action，是最经典的 Agent 范式（K5 深入）。
- **Plan-and-Execute**：先整体规划再逐步执行（K6）。
- **多智能体协作**：多个角色（规划者/执行者/评审者）消息传递（K8）。
- **框架**：LangChain / LangGraph / AutoGen 等（K10）。本教学在 K10 之前用纯 Python 实现，先理解本质。

## 五、常见陷阱
1. **把"调一次 LLM"当成 Agent**——没有循环就不是 Agent。
2. **工具结果不回灌**——观察没喂回模型，模型看不到执行结果，循环断了。
3. **没有终止条件**——无限循环烧钱；必须有"最终答案"或"步数上限"双保险。
4. **让模型直接出结果而不是出决策**——模型只该决定"调什么、填什么参数"，执行与结果由代码负责（安全、可控）。
