## 第 1 章 基础：LLM API、Prompt、Python

**是什么**：大模型（LLM）是一个"给你文字、还你文字"的函数。我们通过 HTTP 接口（如 OpenAI 兼容 API）调用它；Prompt 就是你写给它的指令。

**怎么用**：装好 SDK，用 API Key 发起一次对话请求。

**怎么用代码学懂**：先别背概念，跑通一次"问→答"，再改 prompt 看输出变化，你就懂了。

```python
from openai import OpenAI
client = OpenAI(api_key="YOUR_KEY")              # 兼容任意 OpenAI 风格服务
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "你是一名严谨的助教，只给要点。"},  # 系统提示
        {"role": "user",   "content": "用三句话解释 Agent。"},
    ],
)
print(resp.choices[0].message.content)
```

**Prompt 三件套**：系统提示（定角色/规则）+ 用户提示（具体问题）+ 示例（few-shot，给样例让模型照着做）。改 system 内容，输出风格立刻变——这就是 Prompt Engineering 的全部直觉。

**小项目（独立可跑）**：把上面脚本改成读命令行参数作为 user 输入，循环对话。目标：确认你能稳定调通 API。

## 第 2 章 工具调用 Function Calling

**是什么**：让模型"不直接回答，而是决定调用哪个函数、填什么参数"，由你的代码真正执行，再把结果喂回模型。这是 Agent 能"动手"的根本。

**怎么用**：声明工具 schema（名称/描述/参数），在请求里带上 `tools`，模型返回 `tool_calls`，你执行后把结果作为 `tool` 角色消息回传。

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询城市天气",
        "parameters": {"type": "object",
                       "properties": {"city": {"type": "string"}},
                       "required": ["city"]},
    },
}]
# 第一次请求带 tools；若 resp 含 tool_calls，就执行函数并把结果回传：
msg = resp.choices[0].message
if msg.tool_calls:
    args = json.loads(msg.tool_calls[0].function.arguments)
    result = get_weather(args["city"])        # 你的真实代码
    messages.append(msg)                       # 先存模型那句"我要调工具"
    messages.append({"role": "tool", "tool_call_id": msg.tool_calls[0].id,
                     "content": result})       # 再存执行结果
```

**怎么学懂**：把 `get_weather` 写成永远返回固定字符串，观察模型如何生成参数、你如何回传——理解"模型只出决策，不出结果"这一关键分野。

**小项目**：给模型两个工具（天气 + 计算器），问它"北京天气如何，并算 23*17"。看它是否分两步调用。

## 第 3 章 记忆 Memory

**是什么**：Agent 没有天生记忆，所谓"记忆"就是你在 messages 里保留历史。短期记忆=对话列表；长期记忆=外部存储（文件/向量库）。

**怎么用**：每轮把历史 messages 一起发给模型；超长时截断或摘要。

```python
memory = []                                   # 短期记忆
def chat(user_text):
    memory.append({"role": "user", "content": user_text})
    resp = client.chat.completions.create(model=M, messages=memory)
    memory.append(resp.choices[0].message.model_dump())   # 连同助手回复一起存
    return resp.choices[0].message.content
```

**怎么学懂**：连续问"我叫什么？"——若不保留 memory，模型必答错；保留后答对。这就是记忆的最小真相。

**小项目**：加一个"总结记忆"函数，当 memory 超过 N 条就摘要成一条 system 消息，模拟长期记忆压缩。

## 第 4 章 检索增强 RAG

**是什么**：先根据用户问题从知识库**检索**相关片段，拼进 prompt 再让模型**生成**答案。解决"模型不懂你的私有资料"和"幻觉"两类问题。

**怎么用**：①切分文档 ②向量化存库 ③查询时向量检索 top-k ④拼进上下文。

```python
# 极简版：用关键词命中代替向量（真实项目换向量库即可，结构不变）
CORPUS = {"mcp": "...", "rag": "...", "agent": "..."}
def rag(query):
    hits = [v for v in CORPUS.values() if query.lower() in v.lower()]
    context = "\n".join(hits) or "（无相关文档）"
    return ask(f"根据资料回答：{query}\n资料：\n{context}")   # ask=第1章的调用
```

**向量数据库做什么**：把文字变成向量，按"语义相似"检索（"大模型"能命中"LLM"）。主流：Milvus（国产首选）、Qdrant、pgvector。本教程用内存字典演示流程，替换 `rag()` 里的检索函数为向量库查询即升级。

**小项目（独立）**：准备 5 段 txt，实现切分→检索→问答，问一个只在文档里出现的细节，验证答案来自检索而非模型凭空编。

## 第 5 章 Agent 主循环与规划（ReAct）

**是什么**：Agent = 循环。每轮：模型思考→决定调工具→执行→看结果→再思考，直到能回答。这就是 ReAct（Reasoning + Acting）。规划则是先列步骤再逐步执行。

**怎么用**：把第2章（工具）与第3章（记忆）套进一个 while 循环。

```python
def agent(user_goal, max_steps=5):
    messages = [{"role": "user", "content": user_goal}]
    for _ in range(max_steps):
        resp = client.chat.completions.create(model=M, messages=messages, tools=tools)
        msg = resp.choices[0].message
        if not msg.tool_calls:                 # 模型认为可以回答了
            return msg.content
        for call in msg.tool_calls:            # 逐个执行工具
            args = json.loads(call.function.arguments)
            result = dispatch(call.function.name, args)   # 路由到真实函数
            messages.append(msg)
            messages.append({"role": "tool", "tool_call_id": call.id, "content": result})
    return "（达到步数上限）"
```

**怎么学懂**：打印每一轮的 messages，你会看到"思考→调工具→看结果"在循环里生长。这就是 Agent 的全部本质。

**补充：这就是 Agent Harness（智能体运行时）。** 驱动 LLM 不断"思考→调工具→看结果"循环执行的那层外层代码，行业里叫 **Agent Harness**。本项目的 `项目教学区_Labs/agent_core/`（见 `项目结构说明.md`）就是这个 harness 的最小实现；第10章提到的 LangGraph 等框架，是它的"成品形态"——先自己写一遍，再换框架才不会迷路。

**小项目**：接第2章的天气+计算器，问"上海天气怎样？如果气温高于20度就帮我算 100/气温"。看循环如何自主选择工具链。

## 第 6 章 多智能体协作

**是什么**：一个 Agent 太累就拆成多个：规划者拆任务、执行者干活、评审者挑错。它们通过消息传递协作。

**怎么用**：复用第5章的 `agent()`，给不同角色不同的 system 提示与工具集，再写一个"主管"把子 Agent 的输出串起来。

```python
planner = agent("把'写周报'拆成3步", system="你是项目经理，只输出步骤列表")
worker  = agent(f"执行：{planner}", system="你是执行者，调用工具完成任务")
reviewer= agent(f"检查：{worker}", system="你是评审，只说通过或问题")
```

**怎么学懂**：让三个角色 system 不同，观察同一个 `agent()` 函数如何"换身份"。理解"多智能体 = 同一引擎 + 不同提示 + 消息串联"。

**小项目**：规划者 + 执行者两角色，完成"查北京天气并写成一句话短信"。

## 第 7 章 动手做 MCP 服务（真实实例）

**是什么**：MCP（Model Context Protocol）是统一标准——你的工具/数据只要按它暴露，任何支持 MCP 的客户端（Claude、IDE 插件等）都能直接接入，不用为每个应用重写适配。

**怎么用（已做好的实例）**：`tutorial/code/mcp_demo/server.py` 是一个**纯标准库、零依赖**的 MCP 服务，通过 stdio 上的 JSON-RPC 2.0 暴露一个 `doc_search` 工具。运行 `python test_client.py` 实测输出：

```
initialize -> protocolVersion=2024-11-05, serverInfo=doc-search-mcp
tools/list -> 工具 doc_search（参数 query:string）
tools/call -> "MCP（Model Context Protocol）是 Anthropic 提出的开放协议..."
```

**核心代码（server.py 关键段）**：
```python
def handle(message):
    method, msg_id = message.get("method"), message.get("id")
    if msg_id is None: return None                      # 通知不回复
    if method == "initialize":  return {...协议版本/能力/服务名}
    if method == "tools/list":   return {"tools": [doc_search_schema]}
    if method == "tools/call":   return call_tool(...)  # 真正执行
```

**怎么学懂**：MCP 不难，就是"客户端问有哪些工具 → 你回 schema → 客户端调 → 你回结果"三段对话。把 `call_tool` 里换成查数据库、读文件，你的任意能力就 MCP 化了。

**接入项目（第10章集成）**：在 Agent 里加一个 MCP 客户端，初始化时 `tools/list` 拉取远程工具，把它们伪装成第2章的本地工具交给 `dispatch()`，Agent 即可调用远程能力，无需改一行业务代码。

## 第 8 章 动手做 Skill 能力模块（真实实例）

**是什么**：Skill 是"可复用能力包"——一个名字 + 描述 + 触发词 + 处理函数。Agent 在主循环里识别到触发词，就加载并调用它。比把功能写死在代码里更灵活、可插拔。

**怎么用（已做好的实例）**：`tutorial/code/skill_demo/` 含 `SKILL.md`（元数据）+ `handler.py`（处理函数）+ `run_skill.py`（加载器）。运行 `python run_skill.py` 实测：

```
触发词: ['检索', '知识库', '查资料', '找文档']
调用结果: RAG 先检索再生成，降低幻觉。
```

**SKILL.md（frontmatter 即契约）**：
```markdown
---
name: doc-search
description: 需要从内部知识库检索资料时使用。
triggers: [检索, 知识库, 查资料, 找文档]
---
```

**加载器关键逻辑（run_skill.py）**：
```python
def load_skill(name):
    meta = parse_frontmatter("SKILL.md")        # 读名称/描述/触发词
    handler = importlib.import_module("handler") # 动态导入处理函数
    return meta, handler
def invoke(name, query): return load_skill(name)[1].search(query)
```

**怎么学懂**：Skill 的精髓是"元数据驱动"——Agent 不 hardcode 功能，而是遍历目录下所有 SKILL.md，按 triggers 匹配再加载。新增能力 = 丢一个文件夹进去。

**接入项目（第10章集成）**：在第5章 `agent()` 加一步"意图识别"：每轮先看用户输入是否命中某 Skill 的 triggers，命中则直接 `invoke()`，否则走 LLM 工具循环。这样私有能力优先、通用能力兜底。

## 第 9 章 评估与安全（工程必做）

**是什么**：上线前必须证明"它真的行"且"不会乱来"。

**怎么用（检查清单式，每条都可做成小测试）**：
- **正确性**：用固定题库跑，比对预期（如 RAG 必须引用到文档片段）。
- **工具安全**：工具调用前做参数白名单 + 危险操作（删文件/发邮件）需人工确认。
- **成本控制**：每轮记 token 与费用，超阈值中断。
- **抗注入**：用户输入里藏"忽略以上指令"时，系统提示仍优先。
- **可观测**：把每轮 messages 落盘，出事能复盘。

**小项目**：给第5章 Agent 加一个 `budget(max_steps, max_cost)`，超限即停，验证"失控可被拦住"。

## 第 10 章 综合：把它们接起来

**是什么**：单个技术都会了，现在用一条主线串成"能用的 Agent 系统"。

**怎么用（集成骨架）**：以第5章 `agent()` 为主循环，向上挂：
- 第1–3章：LLM 调用 + Prompt + Memory
- 第2/4章：本地工具 + RAG 检索
- 第7章：MCP 客户端拉远程工具，并入 `tools`
- 第8章：Skill 触发器，优先于 LLM 处理私有意图
- 第9章：步数/成本预算包裹整个循环
- 第6章：把 `agent()` 复制成多角色即多智能体
- 第11章（框架）：以上全用纯 Python 实现；这个主循环本身就是本项目的 **Agent Harness**，想省事可把它整体换成 LangGraph，概念一一对应

**一句话收口**：你从第1章的"一次对话"出发，每章加一个齿轮，到第10章已是一个会记忆、会检索、会调远程工具、可插拔 Skill、带安全预算的 Agent。MCP 与 Skill 不是装饰，而是让系统"向外连、向内扩"的两个真实接口——代码已在 `tutorial/code/` 跑通，复制即接入。
